# 交付範圍與後續規劃

系統設計見 [DESIGN.md](DESIGN.md)，技術決策見 [DECISIONS.md](DECISIONS.md)。目前版本涵蓋 P0 至 P6，使用可重現的模擬資料驗收。

## 已實作

| 階段 | 交付內容 | 驗收 |
| --- | --- | --- |
| P0 開發環境 | Docker Compose、健康檢查、遷移與品質檢查 | API 可連到 PostgreSQL。GitHub Actions 工作流程已定義，遠端執行結果待驗證 |
| P1 主資料 | 製程、機台、檢驗項目、料號、批號、批號關係與進出站；主資料初始化工具 | 可從空資料庫遷移並載入主資料，重跑可預覽差異 |
| P2 報表匯入 | 四種 CSV／Excel 來源、正規化、整檔拒絕、來源列欄與重傳判定 | 21 份樣本逐檔核對結果與筆數。數值有衝突時保留原量測 |
| P3 操作與查詢 | 上傳、匯入歷史、Excel 錯誤報告、量測查詢和分頁 | 可從工作頁完成上傳、查詢、退件報告下載及重傳查驗 |
| P4 偵測率評估 | 可重跑的匯入評估腳本 | 驗證檔案判定、錯誤位置、召回率、誤報與自動修正，結果見 [README](../README.md#匯入偵測率) |
| P5 批號追溯 | 批號詳情、上下游追溯、進出站與 Q-time | 可由檢驗紀錄追查原料或生產批，並查詢等待與超時狀態 |
| P6 統計製程管制 | I-MR 管制圖、固定基準、異常規則與批號連結 | 可從已入庫資料產出雙圖，也可用模擬事件重跑漂移與突變驗證 |

## 驗證入口

- [匯入與查詢試跑](../README.md#試跑完整匯入)
- [追溯與等待時間試跑](../README.md#試跑批號追溯)

- `tests/integration/test_p3_flow.py` 涵蓋報表匯入及 API 流程。

## 後續規劃

| 階段 | 範圍 |
| --- | --- |
| P7 服務層與 MCP | 整理讀取服務，提供有輸入限制及稽核的唯讀工具 |
| P8 調查評估 | 以模擬事件比較模型的根因命中率及證據品質 |
| P9 格式範本 | 以人工核准流程管理新報表的欄位對應範本 |

歷史量測值的更正流程另行規劃。一般匯入遇到同一量測的不同數值時整份退件。
