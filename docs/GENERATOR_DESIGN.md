# Inspection Trace｜PCB／載板製程髒資料產生器設計

> 產生器負責：模擬一座載板廠的生產與檢驗，輸出各種「現場格式」的檔案，
> 再刻意弄髒，並為每一個埋入的錯誤留下正確答案。
>
> **情境參考公開產業資訊，所有數值皆為模擬，不代表任何公司的真實製程或規格。**

---

## 0. 模擬範圍與資料來源

情境採用簡化的 ABF 載板增層製程，包含壓膜、雷射鑽孔、除膠渣、化學銅與線路製作。站點代碼、規格值、等待時間上限、機台及檢驗紀錄均為模擬設定，用於重現匯入與追溯情境。

產業背景參考 [Chip Scale Review 的大面板檢測文章](https://ontoinnovation.com/wp-content/uploads/2025/08/Using-2D.3D-Tech-to-Overcome-Challenges-of-Large-Area-Panel-Insp-and-Metrology_CSR_Jun_2024.pdf)。

---

## 1. 產生器的四層結構

```
config.yaml（情境、規模、亂數種子、髒資料比例）
        |
        v
[1] 主資料層   站點、機台、檢驗項目、料號、原料批
        |
        v
[2] 模擬層     批號流經各站 -> 量測值 -> 製程事件（漂移、突變、Q-time 超時）
        |        產出：乾淨的長表（long format）+ 事件答案清單
        v
[3] 呈現層     依「資料來源」輸出成不同格式：機台匯出 CSV、站點寬表 Excel、
        |        人工抄錄 Excel、化驗 PDF
        v
[4] 弄髒層     依來源特性埋入錯誤 -> 髒檔案 + 每個錯誤的答案清單
```

**關鍵原則：**先產生「真相」（乾淨資料和事件），再從真相渲染出檔案，最後才弄髒。
這樣任何一筆髒資料都能對回原本的正確值。

## 2. 主資料層

### 2.1 製程路線（簡化的 ABF 載板）

```
核心板：
  C10 裁板 -> C20 機械鑽孔 -> C30 鍍通孔／塞孔 -> C40 內層線路 -> C50 內層 AOI

增層（每一層重複一次，例如兩側各 2 層）：
  B10 ABF 壓膜 -> B20 雷射鑽孔 -> B30 除膠渣 -> B40 化學銅
  -> B50 曝光顯影 -> B60 電鍍銅 -> B70 去膜／閃蝕 -> B80 增層 AOI

後段：
  F10 防焊 -> F20 表面處理 -> F30 成型 -> F40 電測 -> F50 終檢（含翹曲）
```

先做「核心板 + 1 層增層 + 後段」就夠；增層數做成設定值，之後再加。

### 2.2 檢驗項目（數值為模擬設定）

| 站點 | 項目代碼 | 名稱 | 單位 | 資料型態 | LSL | 目標 | USL |
|---|---|---|---|---|---|---|---|
| C40 | `CORE_LW` | 內層線寬 | μm | 連續 | 45 | 50 | 55 |
| B10 | `ABF_THK` | ABF 介電層厚度 | μm | 連續 | 27 | 30 | 33 |
| B20 | `VIA_TOP_D` | 雷射孔上孔徑 | μm | 連續 | 55 | 60 | 65 |
| B20 | `VIA_BOT_D` | 雷射孔下孔徑 | μm | 連續 | 40 | 45 | 50 |
| B40 | `ELESS_CU` | 化學銅厚度 | μm | 連續 | 0.7 | 1.0 | 1.3 |
| B60 | `PLT_CU` | 電鍍銅厚度 | μm | 連續 | 13 | 15 | 17 |
| B70 | `BU_LW` | 增層線寬 | μm | 連續 | 15 | 18 | 21 |
| B80 | `AOI_DEF` | AOI 缺陷數（開路＋短路） | 個／片 | 計數 | — | 0 | 3 |
| F10 | `SR_THK` | 防焊厚度 | μm | 連續 | 10 | 15 | 25 |
| F20 | `NI_THK` | 鎳厚 | μm | 連續 | 3 | 5 | 7 |
| F20 | `AU_THK` | 金厚 | μm | 連續 | 0.03 | 0.05 | 0.08 |
| F40 | `ET_FAIL` | 電測不良數 | 個／片 | 計數 | — | 0 | 2 |
| F50 | `WARPAGE` | 翹曲 | μm | 連續 | — | 50 | 100 |

另外一條**製程規則**（不是量測項目）：

| 規則 | 說明 |
|---|---|
| `QTIME_B20_B60` | 雷射鑽孔完成到電鍍銅開始，等候時間不得超過 N 小時（模擬設定，例如 8 小時） |

### 2.3 其他主資料

- 機台：每站 2～4 台，代碼如 `LDR-01`（雷射）、`PLT-03`（電鍍）
- 料號：3～5 個，各有不同的增層數與尺寸
- 原料批：ABF 膜批、銅箔／核心材批、藥水槽批（換槽紀錄），用於追溯和製程事件
- 班別：日班／夜班；作業員用假代號 `OP-0012`

## 3. 模擬層

### 3.1 生產批的移動

- 每個生產批包含 N 片 panel（例如 20 片），依製程路線逐站移動
- 每站有加工時間、排隊時間（隨機），並隨機指派該站的一台機台
- 每站抽檢：例如 3 片 × 5 個量測點；計數型項目逐片記錄
- 少數批會**分批**（例如部分片數重工）或**併批**，寫入批號關係表，用來測試追溯

### 3.2 量測值模型

- 連續型：常態分布，平均值 = 目標值 + 機台偏差 + 事件效果，標準差依項目設定
- 計數型：卜瓦松分布，平均值受事件影響（例如 Q-time 超時會提高缺陷率）
- 每個值同時保留**真值**（模擬層產生的值）

### 3.3 製程事件（給 SPC 和根因分析用的「正確答案」）

| 事件代碼 | 現象 | 效果 |
|---|---|---|
| `EV_DRIFT` | 雷射機台功率逐漸衰減 | 某台雷射機的孔徑逐批變小，直到保養 |
| `EV_PM_RESET` | 機台保養 | 漂移歸零 |
| `EV_MAT_SHIFT` | 換 ABF 膜批 | 之後介電層厚度整體跳一階 |
| `EV_BATH_AGING` | 電鍍藥水老化 | 電鍍銅厚度變異變大，換槽後恢復 |
| `EV_QTIME_OVER` | 雷射到電鍍等太久 | 該批的 AOI 缺陷數、電測不良數上升 |
| `EV_OOS_SPIKE` | 偶發單點異常 | 單一量測點超出規格 |

所有事件寫入 `events.answers.json`：事件代碼、開始與結束時間、影響的機台、批號與項目。
之後 SPC 和異常提醒就能量化「抓到幾個事件、晚了幾批才抓到」。

`EV_QTIME_OVER` 特別有價值：它讓「Q-time 超時 → 後段不良增加」這個關聯藏在資料裡，
系統做到追溯之後，可以示範從電測不良批反查到 Q-time 超時。

### 3.4 輸出（乾淨的真相）

- `truth/records.parquet`（或 CSV）：長表，一列一個量測值，含真值
- `truth/lot_moves.csv`：每批進出站時間、機台
- `truth/lot_links.csv`：批號關係
- `truth/events.answers.json`

## 4. 呈現層：模擬不同的資料來源

現場資料亂，很大一部分原因是**來源不同、格式各異**。每種來源有自己的格式和「容易出的錯」：

| 來源代碼 | 模擬對象 | 格式 | 特徵 |
|---|---|---|---|
| `SRC_MACHINE` | 機台自動匯出（AOI、電測） | CSV，英文表頭，UTF-8 | 時間戳是 Unix 時間或 ISO 格式；很少人工錯誤，但可能有斷檔或重複匯出 |
| `SRC_STATION` | 站點日報（雷射、電鍍） | Excel 寬表：一列一片，P1～P5 量測點橫向排開 | 表頭別名多、單位寫在表頭（例如「孔徑(um)」） |
| `SRC_MANUAL` | 人工抄錄表 | Excel，有標題列、填表人、合併儲存格、合計列 | 錯誤率最高：漏填、全形數字、打錯批號、手寫轉打字 |
| `SRC_LEGACY` | 舊系統匯出 | CSV，**Big5（CP950）編碼** | 欄位名稱是縮寫，日期是 `1151120`（民國年）這類格式 |
| `SRC_LAB` | 化驗或表面處理報告 | 固定版面 PDF | 文字擷取會產生斷字空格、換行錯位（P10 規劃） |

每份檔案的命名也模擬現場：`雷射站_日報_20261120_夜班.xlsx`、`AOI_export_B80_1732080000.csv`。

## 5. 弄髒層

### 5.1 錯誤分三類

| 類別 | 系統應有的行為 | 例子 |
|---|---|---|
| **A. 應自動修正** | 正規化後入庫，記錄修正過程 | 表頭別名、單位 mil→μm、日期格式不一、全形數字、前後空白 |
| **B. 應拒絕** | 產生錯誤代碼，整份檔案不入庫 | 必填空白、非數值、批號格式錯、參照不存在、物理上不可能的值、檔內重複 |
| **C. 系統抓不到（刻意設計）** | 正常入庫；驗證層無能為力，交給 SPC 或人工 | 數字對調（25.3 打成 23.5，仍在合理範圍）、選錯機台但機台存在 |

C 類資料符合匯入規則，需要透過製程訊號或人工比對才能辨識，因此不計入匯入驗證的召回率。

### 5.2 弄髒操作清單（每個都是一個獨立函式）

| 代碼 | 類別 | 操作 | 適用來源 |
|---|---|---|---|
| `D_HEADER_ALIAS` | A | 表頭換成別名：`銅厚`、`Cu厚度`、`copper_thk` | STATION、MANUAL |
| `D_UNIT_MIL` | A | 數值換算成 mil 並標示 mil | STATION、MANUAL |
| `D_DATE_FORMAT` | A | 日期改成 `2026/11/20`、`20261120`、Excel 序號、民國年 | 全部 |
| `D_FULLWIDTH` | A | 數字改成全形：`２５．３` | MANUAL |
| `D_WHITESPACE` | A | 前後加空白、批號中間混入空白 | MANUAL |
| `D_LAYOUT_NOISE` | A | 加標題列、填表人列、合計列、合併儲存格 | MANUAL |
| `D_ENCODING_BIG5` | A | 用 Big5 存檔 | LEGACY |
| `D_REQUIRED_BLANK` | B | 必填欄位清空 | MANUAL、STATION |
| `D_NOT_NUMERIC` | B | 量測值改成 `N/A`、`1.2.3`、`—`、`OK` | MANUAL |
| `D_LOT_TYPO` | B | 批號少一碼、多一碼、字母數字混淆（O 與 0） | MANUAL |
| `D_REF_UNKNOWN` | B | 機台代碼改成不存在的值 | STATION、MANUAL |
| `D_PHYSICAL_IMPOSSIBLE` | B | 厚度為負數、孔徑為 0 | 全部 |
| `D_DUP_ROW` | B | 同檔內複製一列 | MACHINE、MANUAL |
| `D_TRANSPOSE` | C | 數字對調但仍在合理範圍 | MANUAL |
| `D_WRONG_MACHINE` | C | 換成同站另一台存在的機台 | MANUAL |
| `F_DUP_FILE` | 冪等 | 同一份檔案再輸出一次（檔名不同、內容相同） | 全部 |
| `F_TRUNCATED` | B | 檔案在中間截斷 | MACHINE |
| `F_WRONG_TEMPLATE` | B | 雷射站的檔案用了電鍍站的範本 | STATION |

**注意「超出規格」不在這張表裡。**超出 USL／LSL 是品質異常（由製程事件產生），
不是資料錯誤，應正常入庫。

### 5.3 弄髒比例依來源調整

```yaml
dirty_rates:
  SRC_MACHINE: 0.002   # 機台匯出幾乎不出錯
  SRC_STATION: 0.01
  SRC_MANUAL:  0.05    # 人工抄錄錯最多
  SRC_LEGACY:  0.01
```

另外設定「乾淨檔案比例」，例如 40% 的檔案完全不弄髒，用來驗證系統不會誤報。

### 5.4 答案清單格式

每份髒檔案旁邊放一份同名的 `.answers.json`：

```json
{
  "file": "雷射站_日報_20261120_夜班.xlsx",
  "source": "SRC_STATION",
  "expected_outcome": "REJECT",
  "injections": [
    {
      "op": "D_NOT_NUMERIC",
      "category": "B",
      "expected_error_code": "E_NOT_NUMERIC",
      "sheet": "日報",
      "row": 17,
      "column": "孔徑上(um)",
      "original_value": 59.8,
      "dirty_value": "N/A"
    },
    {
      "op": "D_UNIT_MIL",
      "category": "A",
      "expected_error_code": null,
      "row": 9,
      "column": "孔徑下(mil)",
      "original_value": 45.2,
      "dirty_value": 1.78,
      "expected_normalized_value": 45.2,
      "tolerance": 0.1
    }
  ]
}
```

- A 類：檢查正規化後的值是否在容許誤差內等於原值
- B 類：檢查系統是否回報了對應的錯誤代碼、列、欄
- C 類：系統不需要抓到，但評估報告要列出來，說明限制

**列號要以「最終檔案」為準**：弄髒層若插入標題列或合計列，要回頭修正其他錯誤的列號。
這是實作時最容易出錯的地方。

## 6. 程式結構

```
generator/
├─ config/
│  ├─ scenario.yaml          # 製程路線、項目規格、機台數、事件設定
│  └─ dirty.yaml             # 各來源弄髒比例、啟用的操作
├─ master.py                 # 主資料
├─ simulate.py               # 批號移動、量測值、製程事件
├─ events.py                 # 事件定義與效果
├─ render/
│  ├─ machine_csv.py
│  ├─ station_excel.py
│  ├─ manual_excel.py
│  ├─ legacy_csv.py
│  └─ lab_pdf.py             # 後期
├─ dirty/
│  ├─ registry.py            # 操作代碼 -> 函式
│  ├─ cell_ops.py            # 儲存格層級：別名、單位、日期、全形、非數值……
│  ├─ layout_ops.py          # 版面層級：標題列、合計列、合併儲存格
│  └─ file_ops.py            # 檔案層級：重複、截斷、編碼、錯範本
├─ answers.py                # 答案清單的寫出與列號修正
└─ cli.py                    # python -m generator --scale small --seed 42
```

**設計要點：**

- **固定亂數種子**：同一個 seed 和設定，一定產生完全相同的檔案，測試才穩定
- **規模預設**：`small`（測試用，幾百列）、`medium`（展示用）、`large`（10 萬列以上，測效能）
- **每個弄髒操作都是純函式**：輸入「表格＋位置＋亂數產生器」，輸出「新表格＋答案紀錄」
- 呈現層和弄髒層分開，新增一種檔案格式時，不用重寫弄髒邏輯

## 7. 實作順序

| 階段 | 內容 | 完成標準 |
|---|---|---|
| G1 | 主資料 + 只有核心板路線 + 乾淨長表 CSV | 固定 seed 重跑結果完全相同 |
| G2 | 增層與後段路線、量測值模型、計數型項目 | 各項目分布合理，目標值附近 |
| G3 | 製程事件 + 事件答案清單 | 畫圖肉眼看得到漂移和突變 |
| G4 | 站點寬表 Excel、機台 CSV 兩種呈現 | 乾淨檔案能被匯入管線全數吃下 |
| G5 | 前 5 個弄髒操作 + 答案清單 + 評估腳本雛型 | README 出現第一版偵測率表 |
| G6 | 人工抄錄 Excel、版面雜訊、其餘弄髒操作 | 列號修正正確 |
| G7 | Big5 舊系統 CSV、檔案層級錯誤 | 冪等與編碼處理有測試 |
| G8 | 化驗 PDF（配合主系統 P10） | PDF 能走完同一條管線 |

G1～G5 可以和主系統的 P1～P4 交錯進行：先產生乾淨檔案讓匯入功能有東西吃，
再逐步加入髒資料來驗證。

## 8. 匯入評估

評估腳本以答案清單比對檔案結果、每筆錯誤的列欄位置與代碼，以及正規化後的入庫值。重跑方式與內附樣本結果見 [README 的匯入偵測率](../README.md#匯入偵測率)。
