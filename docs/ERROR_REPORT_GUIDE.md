# 報表退件處理說明

這份說明給上傳檢驗報表的現場人員。上傳後若顯示「退件」，依下面的步驟找出問題、修正後重新上傳。

## 退件代表什麼

- **整份檔案都沒有入庫。** 即使只有一列有問題，其他正確的列也不會寫入。修正後重新上傳整份檔案即可，不會重複入庫。
- **超出規格不會退件。** 量測值超過規格上下限，仍然會正常入庫，交給製程管制圖判斷。退件只代表資料本身有問題，例如缺值、格式錯誤或對不上主資料。
- **有些差異系統會自動修正，不會退件。** 例如日期寫成 `2026/11/20`、單位寫成 `um` 或 `mil`、數字用全形、批號前後有空白。

## 下載錯誤報告

在工作頁的匯入歷史找到這次上傳，下載 Excel 錯誤報告。報告有五欄：

| 欄位 | 意思 |
| --- | --- |
| 列 | 問題在原始檔案的第幾列。從檔案第一列開始算，包含標題與表頭。PDF 則是擷取後的文字列號。**空白表示整份檔案的問題**，例如編碼或表頭 |
| 欄位 | 問題出在哪一欄 |
| 錯誤代碼 | 固定的代碼，對照下表 |
| 說明 | 錯誤原因 |
| 原始值 | 檔案裡實際寫的內容 |

每一列最多只會列出一個錯誤。修正後重新上傳，同一列如果還有其他問題，會在下一次報告中出現。

## 錯誤代碼對照

**整份檔案的問題（「列」為空白）**

| 錯誤代碼 | 常見原因 | 處理方式 |
| --- | --- | --- |
| `E_FILE_FORMAT` | 檔案類型不支援、檔案損壞、沒有資料列、資料量超過上限，或 PDF 不是固定版面 | 確認是 CSV、XLSX 或系統支援的化驗 PDF，單檔不超過 5 MiB |
| `E_FILE_ENCODING` | 檔案編碼不對。舊系統 CSV 應為 Big5，機台 CSV 應為 UTF-8 | 用原系統重新匯出，不要用其他軟體另存 |
| `E_HEADER_UNKNOWN` | 找不到必要欄位，或表頭名稱不是系統認得的寫法 | 對照原始範本的表頭。如果是新格式，請管理者建立匯入範本 |
| `E_HEADER_CONFLICT` | 兩個欄位都對應到同一個意思，例如同時有「批號」和「Lot」 | 刪除重複的欄位 |

**某一列的問題**

| 錯誤代碼 | 常見原因 | 處理方式 |
| --- | --- | --- |
| `E_REQUIRED_MISSING` | 必填欄位空白 | 補上該欄的值 |
| `E_NOT_NUMERIC` | 量測值不是數字、用了千分位逗號，或計數型項目填了小數 | 改成一般數字，小數點使用 `.` |
| `E_DATE_INVALID` | 日期或時間無法辨識 | 改成 `2026-11-20 14:05` 這類格式 |
| `E_UNIT_UNKNOWN` | 單位和檢驗項目不相容，例如厚度填了 `%` | 確認單位，長度類使用 `μm`、`um` 或 `mil` |
| `E_LOT_FORMAT` | 批號格式不對，例如少一碼或打錯字母 | 對照流程卡上的批號重新填寫 |
| `E_OPERATOR_FORMAT` | 操作員代碼格式不對 | 應為 `OP-` 加四位數字，例如 `OP-0012` |
| `E_REF_NOT_FOUND` | 批號、機台、檢驗項目或操作員不存在，或不屬於這一站 | 確認代碼有沒有打錯、站別有沒有放錯。確定代碼正確時，請管理者確認主資料 |
| `E_OUT_OF_PHYSICAL_RANGE` | 數值不可能存在，例如負的厚度或負的缺陷數 | 確認原始紀錄，通常是輸入時多打了負號 |
| `E_DUPLICATE_IN_FILE` | 同一份檔案裡同一筆量測出現兩次 | 刪除重複的那一列 |
| `E_MEASUREMENT_CONFLICT` | 系統裡已經有同一筆量測，但數值不同 | **不要直接改數字重傳。** 先確認哪個值才是正確的，再聯絡管理者處理 |

## 其他狀況

- **顯示「重複上傳」**：這份檔案之前已經處理過，系統不會再入庫一次，歷史紀錄會連到第一次的結果。不需要處理。
- **入庫成功但有警告**：檔案裡有系統沒有使用的欄位。資料已經入庫；如果那一欄其實很重要，請告訴管理者。
- **系統抓不到的錯誤**：數字前後對調（例如 `25.3` 打成 `23.5`）或填成同站的另一台機台，只要值看起來合理，系統無法分辨。上傳前請對照原始紀錄。
